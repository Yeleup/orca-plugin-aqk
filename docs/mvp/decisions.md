## Решения владельца

Дословно, с датой и вопросом, на который владелец отвечал.

### 2026-11-25 — блок 1: цель, пользователи, главные сценарии

- Вопрос: «ТЗ MVP плагина Orca для agent-queue-kit, блок 1. Какую проблему решает плагин? Можно выбрать несколько.»
  Варианты сессии: «Видеть очередь в Orca» (панель в боковой части Orca: задачи очереди по проектам — ждут, в работе,
  заблокированы, влиты, — их PR и итоги ревью; не нужно открывать GitHub и терминал); «Отвечать на блокировки»
  (уведомление Orca, когда задача получила agent:blocked или MVP ждёт приёмки; владелец читает вопрос и отвечает прямо
  из Orca); «Ставить и обновлять кит» (установка и автообновление agent-queue-kit через каталог плагинов Orca вместо
  bin/activate + install — то, что проверял пробный плагин agent-queue-kit-probe); «Здоровье очереди» (итог
  agent-queue doctor, сторожа и автоматизаций в строке состояния Orca; разлад виден сразу, и его можно починить
  кнопкой).
  > тоже что и agent-queue-kit. Мы поменяем реализацию на плагин. Который максимально будет использовать функционалы самого orca и будет работать в Mac, Windows, Linux
- Вопрос: «Кто будет пользоваться плагином?» Варианты сессии: «Только я» (один владелец на своих компьютерах; кит у
  него уже стоит, проекты свои); «Я и команда» (несколько человек с китом на своих компьютерах; каждый видит свои
  проекты; роли одинаковые); «Любой в Orca» (публичный плагин в каталоге Orca для всех; плагин должен работать и там,
  где кита нет, — объяснить, что поставить).
  > Любой в Orca
- Вопрос: «Какие сценарии главные для MVP? Можно выбрать несколько.» Варианты сессии: «Утренний обзор» (открыть Orca
  и сразу увидеть, что влито за ночь, что в работе и что ждёт владельца); «Ответ на блокировку» (уведомление о
  заблокированной задаче, вопрос координатора и ответ из Orca: ответ уходит комментарием в issue, и метка снимается);
  «Задача без терминала» (поставить задачу в очередь проекта из Orca: заголовок и текст, без agent-queue enqueue в
  терминале); «Стоп и пуск очереди» (остановить или запустить очередь и автопилот проекта одной кнопкой, то есть
  выключить или включить его автоматизации Orca).
  > тоже что и agent-queue-kit

### 2026-11-25 — блок 1, уточнение: координатор, агенты, проекты на ките

- Вопрос: «Блок 1, уточнение. Сейчас в ките задачу ведёт агент-координатор: автоматизация Orca раз в 5 минут
  запускает Claude с навыком agent-queue, а он вызывает bash-команду agent-queue. API плагина Orca умеет сам создавать
  worktree, запускать в них агентов с заданием, следить за их статусом и читать терминал. Кто ведёт задачу в плагине?»
  Варианты сессии: «Код плагина (Recommended)» (воркер плагина сам берёт задачу, создаёт worktree Orca, запускает
  исполнителя и ревьюера через Orca, ждёт их статус, гоняет круги ревью, открывает PR и мержит после чистого ревью и
  зелёных тестов; LLM нужны только исполнителю и ревьюеру: предсказуемо, меньше токенов, без bash); «Агент, как в
  ките» (как сейчас: автоматизация Orca запускает агента-координатора с навыком; плагин даёт ему команды вместо
  bash-скрипта и панель в Orca).
  > Код плагина (Recommended)
- Вопрос: «Какие агенты делают и ревьюят задачи в плагине?» Варианты сессии: «На выбор (Recommended)» (любые агенты,
  которые запускает Orca, выбираются в настройках проекта: исполнитель отдельно, ревьюер отдельно; по умолчанию
  Claude делает, Codex ревьюит); «Claude и Codex, как в ките» (жёстко: Claude делает, Codex ревьюит; у пользователя
  должны быть оба).
  > На выбор (Recommended)
- Вопрос: «Что с проектами, которые уже работают на нынешнем agent-queue-kit (их очереди GitHub, .agent-queue/ и
  открытые задачи)?» Варианты сессии: «Совместимо (Recommended)» (плагин читает и ведёт те же очереди: те же метки
  agent, agent:in-progress и agent:blocked, тот же формат issue и .agent-queue/config.json; проект переходит на плагин
  без переделки, но два координатора на одном проекте не работают); «Свой формат» (плагин не связан форматом кита;
  переход нынешних проектов — отдельная работа после MVP, до неё они живут на ките).
  > Свой формат

### 2026-11-25 — блок 2: данные и интеграции

- Вопрос: «Блок 2 (данные и интеграции). Где живут задачи очереди плагина?» Варианты сессии: «Issues GitHub
  (Recommended)» (задача — issue с метками плагина в его формате; история, вопросы и ответы — в GitHub, PR там же;
  видно с любого компьютера и телефона); «GitHub и GitLab» (то же, но уже в MVP и для GitLab — issues и merge
  requests: Orca работает с обоими; MVP заметно больше); «Только в Orca» (задачи — в хранилище плагина на этом
  компьютере, без issues; GitHub нужен только для PR или мерж локально; с другого компьютера задач не видно).
  > Issues GitHub (Recommended)
- Вопрос: «Как плагин работает с GitHub?» Варианты сессии: «Через gh (Recommended)» (как в ките: команда gh с её
  входом — gh auth login; плагин не хранит токенов; gh есть на Mac, Windows и Linux, и агентам он всё равно нужен для
  PR); «Токен в плагине» (пользователь вводит токен GitHub в настройках плагина, он хранится в секретах Orca; плагин
  ходит в API GitHub сам, без gh).
  > Через gh (Recommended)
- Вопрос: «Где хранятся настройки проекта: команда тестов, базовая ветка, агенты, правила для заданий?» Варианты
  сессии: «Файл в репозитории (Recommended)» (файл настроек плагина в проекте: одинаков на всех компьютерах, агенты его
  видят, его история в git; панель плагина помогает его заполнить); «В Orca» (настройки проекта живут в хранилище
  плагина на этом компьютере, репозиторий не меняется; на другом компьютере их надо задать снова).
  > Файл в репозитории (Recommended)
- Вопрос: «Как плагин узнаёт, что тесты задачи прошли (без этого PR не вливается)?» Варианты сессии: «Плагин гоняет
  сам (Recommended)» (перед мержем плагин сам запускает полную команду тестов проекта в worktree задачи на её коммите
  и сам записывает итог — код выхода, вывод; скрипт записи в проектах не нужен); «Скрипт проекта, как в ките» (итог
  пишет сама команда тестов проекта своим скриптом записи, когда её запускает исполнитель; плагин только читает файл
  итога).
  > Плагин гоняет сам (Recommended)

### 2026-11-25 — блок 3: состав MVP, языки, сроки, технология интерфейса

- Вопрос: «Блок 3. Что из agent-queue-kit входит в MVP плагина? Можно выбрать несколько. Ревью документов Codex и
  согласование макетов из правила входа сессия предлагает отложить на после MVP — если нужны сразу, напишите в
  Other.» Варианты сессии: «Ядро очереди» (поставить задачу — из панели Orca или из сессии агента по правилу в
  CLAUDE.md/AGENTS.md, зависимости между задачами; плагин берёт задачу: исполнитель в worktree, ревьюер, круги
  замечаний, PR, тесты, мерж; блокировка — с вопросом владельцу и его ответом); «Панель и уведомления» (панель очереди
  по проектам в Orca — ждут, в работе, заблокированы, влиты, — статус в строке состояния, уведомления Orca о
  блокировках и мержах, стоп и пуск очереди проекта); «Подключение и сторож» (подключить проект из панели — файл
  настроек, метки, правило для сессий — и проверить его, как init и doctor; сторож замечает зависшие задачи и
  потерянных агентов и возвращает их в работу); «Автопилот MVP» (старт MVP — вопросы, ТЗ, дизайн, план, как сейчас
  делает навык старта, — план в очередь, решения без остановок, деление застрявших задач, приёмка на стенде; самая
  большая часть).
  > Ядро очереди,Панель и уведомления,Подключение и сторож,Автопилот MVP
- Вопрос: «На каких языках интерфейс плагина и тексты, которые он пишет в GitHub (комментарии к задачам, описания
  PR)?» Варианты сессии: «Английский и русский (Recommended)» (два языка интерфейса, выбор в настройках плагина;
  тексты в GitHub — на языке из настроек проекта: плагин для всех, но и для вас); «Только английский» (интерфейс и
  тексты в GitHub на английском, русский — после MVP); «Только русский» (как сейчас в ките, английский — после MVP).
  > Английский и русский (Recommended)
- Вопрос: «Есть ли срок для MVP?» Варианты сессии: «Без срока» (готово, когда очередь доведёт план; состав важнее
  срока); «Две недели» (MVP нужен через две недели; то, что не успевает, уходит во «Вне MVP»); «Месяц» (MVP нужен через
  месяц).
  > Без срока
- Вопрос: «На чём строятся экраны плагина? Orca даёт панелям два способа.» Варианты сессии: «Компоненты Orca
  (Recommended)» (панель на готовых компонентах Orca — TSX без сборки: списки, таблицы, вкладки, кнопки, поля,
  Markdown, бейджи; выглядит как сама Orca и сам следует её светлой и тёмной теме; доска дизайна — в виде Orca);
  «Своя страница» (панель — своя HTML-страница в изолированном фрейме, со своим CSS; любой вид, но тему и вёрстку надо
  делать самим; доска — свой вид).
  > Компоненты Orca (Recommended)

### 2026-11-25 — блок 4: только владелец, название

- Вопрос: «Блок 4 (только владелец). Как плагин попадает к „любому в Orca“?» Варианты сессии: «Каталог Orca, публикует
  владелец (Recommended)» (MVP готовит релиз — версию, запись для каталога orca plugin release-entry и README; вносит
  плагин в каталог Orca владелец сам, со своего аккаунта, как пробный agent-queue-kit-probe); «Публикация после MVP»
  (в MVP плагин ставится из Git-репозитория — orca plugin install; каталог — когда владелец решит).
  > Каталог Orca, публикует владелец (Recommended)
- Вопрос: «Как проверяется, что плагин работает на Mac и Windows? У вас сейчас Linux.» Варианты сессии: «GitHub
  Actions (Recommended)» (тесты плагина на Linux, macOS и Windows в GitHub Actions, как у пробного плагина; workflow
  добавляет MVP; владелец даёт Actions в репозитории — у частного репозитория минуты считаются); «Владелец руками»
  (автотесты только на Linux; на Mac и Windows владелец проверяет сам при приёмке MVP).
  > GitHub Actions (Recommended)
- Вопрос: «Тестам и приёмке нужна очередь, на которой плагин создаёт issues, PR и мержит. На чём его проверять?»
  Варианты сессии: «Подделки + песочница (Recommended)» (автотесты идут с поддельными gh, git и хостом Orca, как тесты
  кита, — без сети; для приёмки владелец создаёт отдельный тестовый репозиторий GitHub, на котором плагин ведёт
  настоящую очередь); «Только подделки» (и автотесты, и приёмка — только с поддельными gh и Orca; настоящую очередь
  владелец проверяет сам на своём проекте).
  > Только подделки
- Вопрос: «Как называется плагин в Orca (имя в каталоге и заголовок ТЗ)? Сейчас в заготовке временно стоит
  agent-queue-kit.» Варианты сессии: «Agent Queue» (имя «Agent Queue», id agent-queue; коротко и понятно тем, кто не
  знает кита); «agent-queue-kit» (как кит и пробный плагин: имя и id agent-queue-kit).
  > Agent Queue

### 2026-11-25 — уточнение: старт MVP в плагине

- Вопрос: «Автопилот MVP входит в MVP плагина. Где в плагине идёт старт MVP нового проекта (вопросы владельцу, ТЗ,
  дизайн, план — то, что сейчас делает навык /agent-queue-start)?» Варианты сессии: «Агент в терминале Orca
  (Recommended)» (кнопка «Начать MVP» в панели запускает агента — по умолчанию Claude — в терминале Orca с инструкцией

  владелец заполняет поля; документы пишет агент в фоне; уточняющие вопросы агента приходят в панель).

  > Артефакты Orca, как сейчас
